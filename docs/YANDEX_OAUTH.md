# Вход через Яндекс ID (OAuth 2.0)

Поток реализован на серверных Route Handlers Next.js. Без переменных окружения
он **не работает и не имитируется**: `/api/auth/me` возвращает
`{ configured: false, user: null }`, а UI показывает состояние «вход недоступен».

## Переменные окружения

| Переменная             | Назначение                                                      |
| ---------------------- | --------------------------------------------------------------- |
| `YANDEX_CLIENT_ID`     | ID приложения из https://oauth.yandex.ru/                       |
| `YANDEX_CLIENT_SECRET` | Client secret (только на сервере, в браузер не попадает)        |
| `AUTH_URL`             | Публичный origin приложения, `https://…` (или `http://localhost`) |
| `AUTH_SECRET`          | ≥ 32 символов, подпись сессионной cookie (`openssl rand -base64 48`) |

Redirect URI в настройках приложения Яндекса: `${AUTH_URL}/api/auth/yandex/callback`.
Права: «Доступ к логину, имени и фамилии, полу» и «Доступ к портрету пользователя».

## Маршруты

| Метод | Путь                         | Что делает                                                         |
| ----- | ---------------------------- | ------------------------------------------------------------------ |
| GET   | `/api/auth/yandex/login`     | Генерирует `state` + PKCE, кладёт их в httpOnly cookie, редиректит на Яндекс |
| GET   | `/api/auth/yandex/callback`  | Проверяет `state`, меняет `code` на токен, запрашивает профиль, ставит сессию |
| GET   | `/api/auth/me`               | `{ configured, user }` — читает подписанную сессию                 |
| POST  | `/api/auth/logout`           | Удаляет сессионную cookie                                          |

## Меры безопасности

- **CSRF**: случайный `state` (32 байта) в httpOnly cookie, сравнение через `timingSafeEqual`.
- **PKCE (S256)**: `code_verifier` хранится только в httpOnly cookie на 10 минут.
- **Client secret** используется только на сервере при обмене кода на токен.
- **Access token Яндекса не сохраняется**: он нужен один раз для запроса профиля.
- **Сессия** — HMAC-SHA256-подписанный payload (`id`, имя, аватар, план, `exp`) в
  cookie `rc_session`: `httpOnly`, `sameSite=lax`, `secure` в production, TTL 7 дней.
- Причины ошибок, попадающие в URL, ограничены белым списком (`reason=`).
- `AUTH_URL` обязан быть `https://` вне localhost; redirect URI строится из него,
  а не из заголовка `Host`.

## Что нужно дальше (бэкенд)

Сейчас профиль живёт только в cookie. Для реальных метрик (трафик, история,
рефералы, подписка) нужен сервер с БД: при callback создавать/обновлять
пользователя по `yandex:<id>`, а `/api/auth/me` и данные кабинета отдавать из него.
